# תכנית: התראות ווידג'טים (אפליקציית אנדרואיד בלבד)

החלטות הבעלים (2026-10-15):
- **התראות:** כל ארבעת הסוגים: טיסות, תזכורות בשעה, סיכום בוקר, שינויים של שותפים.
- **וידג'ט:** הטיסה הבאה, התוכנית של היום, התקדמות האריזה ותזכורות פתוחות.
- **פלטפורמה:** אפליקציה בלבד. האתר נשאר כמו שהוא.

## איך זה חי לצד האתר
- זה קוד אחד. כל מה שתלוי בטלפון עובר דרך `src/lib/native/*` ונקרא רק כש־`isNative`. באתר הפונקציות ריקות ולא עושות כלום.
- הווידג'ט הוא קוד Android נייטיבי (`android/app/src/main/java/.../widget/`). הוא קורא JSON שהאפליקציה שומרת בטלפון (SharedPreferences) דרך תוסף קטן, `WidgetBridge`.
- מיזוג ל־master מפרסם אתר (שבו לא משתנה כלום) ו־Release חדש לאפליקציה.
- "Release רק כשמשהו באפליקציה השתנה" כבר מכסה את `android/`.

## שלבים (PR לכל שלב)

### N1 — תשתית התראות מקומיות + טיסות
- `@capacitor/local-notifications`, והרשאת `POST_NOTIFICATIONS` (Android 13+) שמתבקשת בפעם הראשונה שמפעילים התראה.
- הגדרות ← "התראות", עם מתג לכל סוג. ברירת המחדל: טיסות פועל.
- טיסה: 24 שעות לפני ("צ'ק־אין נפתח") ו־3 שעות לפני ("זמן לצאת לשדה"), להלוך ולחזור.
- התזמון מתחדש כשהאפליקציה נפתחת וכשפרטי טיסה משתנים. מזהה ההתראה יציב (טיול + סוג), כך שתזמון מחדש מחליף ולא מכפיל.
- לחיצה על ההתראה פותחת את הטיול בטאב הטיסה.
- בדיקות: יחידה לחישוב הזמנים, ובאמולטור: התראה מתוזמנת קיימת (`adb shell dumpsys alarm` / `notification`).

### N2 — תזכורות בשעה
- שדה "שעה" (אופציונלי) בטופס התזכורת. מוסיפים שדה למסמך, בלי להחליף מסמך שלם.
- תזכורת עם שעה מקבלת התראה. סימון "בוצע" או מחיקה מבטלים אותה.

### N3 — סיכום בוקר
- בכל בוקר בימי הטיול (ברירת מחדל 08:00, אפשר לשנות): כמה פריטים יש היום בתוכנית, הפריט הראשון, ומזג האוויר.
- התחזית נלקחת ברגע התזמון.
- מתוזמן לכמה ימים קדימה בכל פתיחה של האפליקציה.

### N4 — וידג'ט
- וידג'ט אחד בגודל 4×2 שמשתנה לפי ההקשר:
  - לפני הטיסה: הטיסה הבאה וספירה לאחור.
  - בזמן הטיול: התוכנית של היום.
  - בכל מצב: X/Y נארזו ותזכורות פתוחות.
- `WidgetBridge.save(json)` נקרא בכל שינוי בנתונים הרלוונטיים, והווידג'ט מתעדכן מיד.
- לחיצה פותחת את האפליקציה במקום המתאים.

### N5 — שינויים של שותפים (Push)
- FCM: האפליקציה שומרת טוקן תחת `users/{uid}`. בחוקי Firestore כל משתמש כותב רק את הטוקן שלו.
- Cloud Functions: טריגרים על שינויים בטיול (הזמנה, הוצאה, פריט חדש) שולחים Push לשאר החברים, לא לזה שעשה את השינוי.
- פריסת Functions דרך GitHub Actions.
- **דורש פעולה של הבעלים:** שדרוג Firebase לתוכנית Blaze (תשלום לפי שימוש, בהיקף הזה כנראה חינם), ואולי הרשאת Functions לחשבון השירות. הבקשה תגיע בהודעה אחת כשמגיעים לשלב הזה.

## כללים
- כל הפעולות הנייטיביות עטופות ב־`try`. אם תכונה נכשלת, האפליקציה ממשיכה לעבוד.
- בלי לשנות מבנה נתונים קיים: רק להוסיף שדות.
